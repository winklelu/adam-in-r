# adam-in-r

Idiomatic R (tidyverse) translations of the functional scenarios commonly
found in SAS ADaM programming — sorting, merging, date derivation,
baseline flags, toxicity grading, and more.

Each scenario is a single, self-contained R file: the original SAS logic
lives in a comment block at the top, and the tidyverse equivalent sits
directly below it, so both are visible side by side in the same file.

All data is synthetic — generated by `R/00_data/simulate_data.R` — and
structured loosely like CDISC SDTM domains (DM, EX, AE, CM, VS, QS, SC,
DS, LB, EG, PC, DV). No real subject-level data is used anywhere in this
repo.

## Why this exists

This project started as a way to demonstrate R proficiency using material
the author already knows well (production ADaM programming patterns), and
is intended to be shared more broadly as a small open reference for
programmers moving between SAS and R.

The source scenario catalogue this repo translates from is a living,
Chinese-language reference note the author keeps separately, based on
real ADaM programs from protocol KX-ORAX-002.

## Requirements

- R (tested with R 4.x)
- Packages: `dplyr`, `tidyr`, `stringr`, `lubridate`, `purrr`, `tibble`

## Running a scenario

Run any file directly from the project root:

```sh
Rscript R/04_adam_core/baseline_flag.R
```

Or open the file in RStudio/VS Code and run it interactively — every
script sources `R/00_data/simulate_data.R` for its input data, so nothing
else needs to be set up first.

## Scenarios intentionally not translated

Two scenarios from the original SAS catalogue are pure SAS
project-management conventions with no meaningful R skill to demonstrate,
so they were left out rather than forced into a file:

- **Clearing the WORK library at the top of every program**
  (`proc datasets ... kill;`) — in R this is just a fresh session or
  `rm(list = ls())`.
- **Log-redirection boilerplate** (`proc printto`) — no R equivalent
  worth demonstrating.

## Adding a new scenario

1. Copy `_template.R` into the relevant `R/<category>/` folder.
2. Fill in the original SAS snippet as a comment, then the tidyverse
   equivalent below it.
3. If new source data is needed, add a generator to
   `R/00_data/simulate_data.R` rather than hard-coding data inline.
4. Add a row to the scenario index table above.
